    Namespace ProvostXMemory.Abstractions

    Classes

    BackendStats

    Stats snapshot of a backend (store or index).

    Chunk

    A chunk produced by splitting a memory record. StartOffset and EndOffset are half-open offsets into the parent record's content (parentContent[StartOffset..EndOffset] == Content); the value -1 means "unset". Chunkers always set both.

    ChunkOptions

    Chunking parameters: structural markers, size and overlap. A trailing chunk shorter than MinChunkLength merges into its predecessor (may exceed the max — max is a packing target, min is a hard floor).

    ConsolidationOptions

    Tuning for one IMemoryService.ConsolidateAsync pass over a scope.

    DedupSimilarityThreshold — cosine above which two records count as near-duplicates (lexical Jaccard fallback when embeddings degenerate). The OLDEST record of each duplicate group is kept, tags are unioned into it, the rest are deleted. ExpireTtl — when on (default), records whose ExpiresAt is past are deleted first. EmitClusterSummaries — when on, the remaining near-duplicate clusters (similarity ≥ the ConsolidationTuning.ClusterJoinThreshold) emit one summary record each, graph-recorded when a graph extractor is wired.

    FusionOptions

    Fusion options: RRF constant and stage weights.

    GraphOptions

    Graph layer options: neighbor fan-out cap, walk depth, retriever behavior knobs.

    MemoryEntryModel

    Logical record model as persisted on disk (JSONL entry shape). Reps and Meta are optional trailing parameters: entries written before they existed (or writers that leave them out) deserialize with null, which the store maps to the record's empty defaults — never a null crash.

    MemoryLoggingOptions

    Logging configuration for the memory service. Off by default — Enabled = false means zero writes, zero log-entry allocations on the hot path, no log directory created. Enabled logging is content-minimized: log lines carry what happened (scope, operation, scores, durations), never record content itself, unless IncludeContent is explicitly set — the default-persisted posture is behavior-evidence without user-content retention.

    Audit mode: Integrity = MemoryLogIntegrity.HashChain appends entries SHA-256 hash-chained to their predecessor (with monotonic sequence numbers) under a serialized gate — any modified or deleted line breaks verification, and LogChainVerifier proves integrity in one pass. RetentionDays triggers the retention sweeper; both file and console sinks are available, hosts inject their own IMemoryLogSink (SIEM, Serilog, …) through the builder.

    MemoryManifest

    On-disk metadata describing the memory root: codecs, counts, versions.

    MemoryRecord

    The unit of remembered knowledge: an immutable record with identity, scope, content, and retrieval hints. Records are created by hosts and persisted through IMemoryService.RememberAsync; retrieval returns them wrapped in ScoredMemoryRecord.

    Retrieval relevance is driven by Content (embedded and lexically indexed), boosted by Tags and Key terms and Category exact matches in the default reranker. Optional Reps add per-modality content (image captions, tables) that is embedded alongside the text and retrievable through the multi-representation retriever.

    MemoryRepresentation

    Additional per-modality content of a record: image captions, tables, audio transcripts, or any parallel content that should be retrievable alongside the record's main text. Each representation is embedded with the host's IVectorEmbedder and indexed under its own vector id (repr|<recordId>|<index>); the multi-representation retriever compares a query against every representation and keeps the best-matching one per record.

    Modality contract: Modality is a tag, not a type system — content is always string. EmbeddingModelHash is optional metadata for hosts that run several embedding models; the vector index namespace guard keys on the model hash + dimension, not on this field.

    MemoryScope

    One isolation boundary of memory: the (Kind, Id) pair every record, index, and log line belongs to. Records written to one scope are structurally invisible to operations on another — the storage root layout pins each scope to its own directory tree and the index registry keys indexes by the exact scope pair.

    Scopes may carry a ParentScope chain for hierarchical fan-out (query plans target a root and resolve child scopes), but lookups never fall through to parents: a query against scope A sees scope A, nothing else, whatever its ancestry.

    MemoryServiceOptions

    The root options record for MemoryService: the host's per-domain tuning, injected once at build time. Each section covers one pipeline concern — Storage (root layout), Vector (backend + dim), Graph (walk tuning), Fusion (RRF weights), Consolidation (dedup/cluster thresholds), Logging

    Section records carry safe defaults; a host that passes all defaults gets the reference pipeline. Optional capabilities (grader, graph extractor, reranker, log sink) are injected via MemoryServiceBuilder rather than this record — options tune behavior, wiring enables capabilities.

    QueryPlan

    Declarative retrieval plan: an ordered set of steps the runner executes.

    QueryPlanStep

    One step of a declarative plan (fan-out namespaces, merge, iterate).

    QueryTokens

    Pure query-text token helpers shared by text-processing packages (keyword rewriting, score-boost reranking). Stateless lookups and a compiled regex only; this class is the architecture-sanctioned pure-function static: no I/O, no ambient state, deterministic.

    RetrievalFilters

    Immutable tag/category/date filter set for retrieval.

    RetrievalProvenance

    Provenance of a scored memory record: which retriever produced it and per-stage scores.

    RetrievalQuery

    A scope-bound retrieval request: what to look for, where to look, and how much to return. Passed to IMemoryService.RecallAsync.

    Scope is authoritative — results are drawn from that scope's indexes only, never from other scopes. Text runs through the full pipeline (embedding + BM25 lexical + fusion + optional rerank/corrective loop); an empty or whitespace text short-circuits to an empty result. TopK bounds the returned records. Filters (tags, category, date-from) are applied after fusion, so they never affect ranking of the candidates they admit. Plan (when set) executes a declarative multi-scope fan-out instead of a single-scope lookup — see QueryPlanRunner.

    RetrievalResult

    The outcome of IMemoryService.RecallAsync: the scored records, best first, plus per-stage diagnostics.

    Records is ordered by Score descending with deterministic tie-breaks by record id. Diagnostics carries one entry per pipeline stage (dense, lexical, fusion, rerank, corrective retries) with durations and stage-specific metrics — feed it to the eval harness for Recall@k/MRR/NDCG.

    RetrievalStageDiagnostics

    Diagnostics of one retrieval stage (scores and timing).

    ScoredId

    A scored hit from a store/index search: scope kind, scope id, id, score.

    ScoredMemoryRecord

    A record matched by a retrieval, its relevance score, and where the score came from. Provenance names the stage that produced the score and carries per-stage subscores (e.g. the fused RRF score plus the rerank-adjusted score), so ranking changes across pipeline stages remain explainable end to end.

    StorageOptions

    FlatJson store options: root folder + durability settings.

    VectorOptions

    Vector index options: backend kind, model hash, dimension, default top-k.

    IMemoryStore

    The durable record store seam. Every method takes the scope explicitly (kind + id) — there is no scope-less operation anywhere in the contract, so a store implementation physically cannot conflate scopes. The default JsonlMemoryStore lays out one records.jsonl per scope directory with transactional rewrites (temp file + atomic move) and tolerant reads (blank lines and legacy entries without Reps/Meta deserialize to defaults).

    Concurrency contract: implementations are not required to be internally thread-safe — IMemoryService serializes store mutations per service instance; direct multi-threaded store access is the host's own synchronization problem.

    Enums

    IndexKind

    The vector index backend family. Flat — exact SIMD scan, the correctness baseline and the best choice up to tens of thousands of vectors. Ivf — deterministic k-means inverted lists; probes only nprobe clusters per query, the sweet spot for large corpora. Hnsw — navigable-small-world graph, highest recall per query latency; built with immutable-index/rebuild semantics and searched with a layered greedy beam (see the architecture patent addendum). Gpu — ILGPU-kernel decoration over a CPU backend with bit-exact fallback when no device exists. All kinds pass one shared conformance suite; results are interchangeable between kinds (FlatJson included, see IVectorIndex).

    MemoryScopeKind

    The isolation axis of a MemoryScope. One record lives in exactly one (Kind, Id) pair; the kind determines what the id conventionally names: Platform (one surface — e.g. per chat platform), Session (one conversation or run), Tenant (one customer — multi-tenant hosts), Purpose (one knowledge base or domain), Custom (host-defined). Kinds map to storage path segments, so cross-kind and cross-id isolation are identical by construction. Unknown on-disk kinds degrade to Custom on read.
