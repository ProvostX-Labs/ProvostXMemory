    Namespace ProvostXMemory.Retrieval

    Classes

    HybridRetriever

    Hybrid retrieval within one scope: dense (vector index) and lexical (BM25-lite index) searches run concurrently over the scope's registered artifacts, are fused via the injected IResultFuser (RRF over "dense"/"lexical" rank lists), resolved against the scope's records, and optionally reranked by an injected IReranker. Scope comes from the query and all registry lookups are scope-exact.

    InMemoryScopeIndexRegistry

    In-memory scope → artifact registry for single-process hosts and test harnesses. Keys are the exact (Kind, Id) pair; lookups never fall through to parent or child scopes.

    KeywordQueryTextRewriter

    Zero-dependency IQueryTextRewriter: distills the query text to its key terms via KeyTerms(string) — stopwords stripped (acronyms preserved), duplicates collapsed, first-appearance order. Empty queries stay empty.

    MultiRepresentationRetriever

    Multi-representation retrieval: instead of scoring whole-record content, the query is embedded once and compared against each representation's precomputed vector for the requested modality. Representation vectors are indexed in the vector index under "repr|<recordId>|<index>" ids (see RepresentationId(string, int)); hits map back to their parent record, per-record scores take the best-matching representation, and per-modality provenance is attached. Scope comes from the query; registry lookups are scope-exact.

    QueryPlanRunner

    Executes a declarative QueryPlan. Each step fans out to its target scopes (target scope strings are "<scope-kind>/<scope-id>" pairs; empty targets mean the query's own scope), runs the injected retriever in every target scope with per-scope ids namespaced, and merges the step lists via the injected IResultFuser. When every step's top score is below WeakEvidenceThreshold, a single second pass runs once against the rewritten text from the injected IQueryTextRewriter; its results replace the first pass. Record resolution happens against each target scope's own snapshot — a record id from scope A never resolves into scope B.

    QueryPlanRunner.QueryPlanRunnerOptions

    Tuning for the plan runner: weak-evidence thresholds and pass behavior.

    RetrievalFilterApplier

    Pure predicate that enforces the RetrievalFilters carried on a RetrievalQuery against resolved records: category exact-match, tag any-match, and date window (From/To) on the record's CreatedAt. A null filter set matches everything, so unfiltered retrieval is behaviorally unchanged. Intentionally static: it is a pure function per the architecture rule.

    Interfaces

    ICorrectiveRetriever

    Grader-gated hybrid retrieval with rewrite loop (corrective).

    IHybridRetriever

    Dense + lexical retrieval in parallel → fused results.

    IMultiRepresentationRetriever

    Query across modalities (multi-representation records).

    IQueryPlanRunner

    Executes a declarative QueryPlan (fan-out namespaces, merge, iterate).

    IQueryTextRewriter

    Rewrites a query's plain text before a second retrieval pass (host-injected; typically an LLM-backed rewriter, a lexical distiller, or a spell corrector). Lives in Retrieval (not Correction) so plan fan-out can iterate without the Correction package as a dependency.

    IScopeIndexRegistry

    Maps a MemoryScope to its per-scope retrieval artifacts. Implementations must be scope-exact: a lookup for scope A never returns an artifact of scope B (no parent fallthrough, no default forwarding) — cross-scope access stays structurally impossible.

    QueryPlanRunner.IScopeResolver

    Resolves target scope strings ("Kind/Id") against a root scope.
