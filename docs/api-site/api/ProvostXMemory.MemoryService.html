    Class MemoryService

    Composition root: takes MemoryServiceOptions plus injected dependencies and owns the configured retrieval pipeline. Remember/Forget/Update maintain the per-scope indexes alongside the store; Recall routes through hybrid → optional corrective → plan (when the query carries one) → optional rerank. Every store access goes through the scope-bound IMemoryStore API, so cross-scope isolation is structural. Per-scope indexes are created lazily and registered scope-exact.

    ConsolidateAsync(MemoryScope, ConsolidationOptions, CancellationToken)

    Runs one consolidation pass over a scope: TTL expiry deletes records whose ExpiresAt is in the past, near-duplicates are detected (embeddings with a lexical fallback), the oldest record of each duplicate group is kept with the group's tags unioned in, and sufficiently large near-duplicate clusters emit a summary record. Survivors and summaries are returned as the consolidated set.

    RecallAsync(RetrievalQuery, CancellationToken)

    Routes the query through the configured retrieval pipeline: hybrid dense+lexical search fused with Reciprocal Rank Fusion, optionally reranked; when a grader is wired, a corrective loop grades candidates, rewrites weak queries, and retries once. Scope comes from the query; results never cross scopes.

    RememberAsync(MemoryRecord, CancellationToken)

    Persists a record and indexes it for retrieval: the record is written to the scope's durable store, then chunks, whole-record, and per-representation entries are embedded and added to the scope's vector index, and the full text is added to the scope's lexical index. A record id that already exists in the scope is rejected.
