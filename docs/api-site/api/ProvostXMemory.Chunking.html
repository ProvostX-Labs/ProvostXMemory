    Namespace ProvostXMemory.Chunking

    Classes

    ChunkIdCodec

    Canonical chunk-id codec: "scopeKind|scopeId|recordId|chunkIndex" (ordinal pipe-separated). Embeds the parent's scope so a chunk id alone is enough to locate its parent record in the store, and keeps record ids from colliding across scopes.

    ChunkIdParts

    The four components of a canonical chunk id.

    ChunkParentResolver

    Resolves a canonical chunk id to its parent record via an IMemoryStore snapshot of the scope embedded in the id. A malformed id or a missing parent record yields null; the chunk index itself is never validated against a live chunk list.

    SizeChunker

    Pure size + overlap splitting for unstructured content. Two modes: geometry (no separator): with Overlap = 0 content is cut at separators (paragraph break → newline → sentence terminator → hard slice of exactly max) with separator whitespace consumed at cuts; with overlap > 0 fixed stride windows (stride = max − overlap, window = max) guarantee consecutive chunks share exactly Overlap characters and no character is lost. Separator mode: words are packed and joined by the separator; Overlap counts shared whole words repeated from the previous chunk's tail (rolling window), so shared text matches word for word.

    StructuredChunker

    Splits record content by markdown structure: headings become their own chunks, each paragraph is a chunk (or sentence-packed pieces when oversized; a single over-max sentence hard-slices). Non-structural mode (RespectStructure = false) delegates to SizeChunker. Overlap is only applied by SizeChunker; structural chunking keeps paragraphs intact. All content is preserved verbatim (modulo whitespace between structural cuts) with exact offsets.

    Interfaces

    IChunker

    Splits a record's content into embedded units for the dense index. Chunks carry exact offsets back into the original content, so a chunk hit resolves to its parent record — the whole record is always what surfaces in results, never the fragment.

    Implementations: StructuredChunker cuts on markdown structure first (headings, paragraphs, then sentences) and only hard-slices oversized content; SizeChunker packs by size with optional overlap — fixed-stride windows in geometry mode, shared whole words in separator mode. Both preserve every character of content across the split (mod whitespace at cut points).

    Chunk ids are scope-qualified (kind|scope-id|record-id|index) — see ChunkIdCodec; ids containing the '|' separator are rejected at compose time.

    IParentResolver

    Resolves chunk ids back to their parent record (parent-document recall).
