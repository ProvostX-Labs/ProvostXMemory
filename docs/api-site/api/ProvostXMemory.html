    Namespace ProvostXMemory

    Classes

    DefaultEvalServiceFactory

    Default eval wiring: a real MemoryService over the transactional JSONL store + own-engine flat index + RRF, powered by the deterministic ClusterHashEmbedder (no real model anywhere). Any host can substitute its own EvalServiceFactory to eval its production wiring instead.

    EvalRunner

    Runs an EvalCaseSet against a freshly built service from an EvalServiceFactory: materializes the corpus records under a fresh temp root, builds indexes per scope, replays every golden query, computes all metrics and breakdowns, checks thresholds, and produces a JSON-serializable EvalReport. The runner never constructs a service itself — hosts control wiring via the factory.

    EvalRunnerOptions

    Per-run knobs for EvalRunner.

    GraphIndexLedger

    Index-time graph maintenance over the scope-pinned IMemoryGraphStore (resolved via IMemoryGraphStoreResolver): per record, the wired IEntityExtractor's entities/relations are upserted for the record's scope only; when a record is forgotten, its mentions are dropped by re-extracting the scope's remaining snapshot. The ledger itself holds no per-record entity cache — graph stores accumulate weight by design, so Forget rebuilds the affected entity mention lists from the surviving records. Scope comes from the record; the resolver is scope-exact by contract.

    MemoryService

    Composition root: takes MemoryServiceOptions plus injected dependencies and owns the configured retrieval pipeline. Remember/Forget/Update maintain the per-scope indexes alongside the store; Recall routes through hybrid → optional corrective → plan (when the query carries one) → optional rerank. Every store access goes through the scope-bound IMemoryStore API, so cross-scope isolation is structural. Per-scope indexes are created lazily and registered scope-exact.

    MemoryServiceBuilder

    Fluent wiring helper for MemoryService. Collects the host's choices and hands them to the MemoryService constructor — still plain constructor injection underneath, no service locator, no ambient container.

    MemoryServicePipelineOptions

    Pipeline wiring knobs layered over MemoryServiceOptions: which extra retrieval stages run during Recall/Remember and maintenance bounds for index updates.

    RootChildScopeResolver

    Default plan-fan-out scope resolution: a target string names either the root scope itself ("<Kind>/<Id>", case-insensitive) or a child scope built via WithParent(MemoryScope) ("<ChildKind>/<ChildId>" over the root). Resolving a child pins the parent, so fan-out targets are always descendants or the root itself — never unrelated scopes.

    Interfaces

    EvalServiceFactory

    Host-pluggable service construction for eval runs: given a fresh root path the host builds an IMemoryService exactly as it does in production. Implementations must return a service with no records yet — the runner owns corpus loadout and index building.

    IMemoryService

    The single public surface of the ProvostXMemory library. Host applications see this interface — plus the options records they pass to MemoryServiceBuilder — and nothing else. Every capability of the library (durable storage, hybrid lexical and dense-vector retrieval, fusion, reranking, optional corrective and graph retrieval, consolidation, and audit-grade logging) is reachable through the members below.

    Scope isolation. Every record belongs to exactly one MemoryScope (platform, session, tenant, purpose, or custom). Every operation is scope-bound; a record written to scope A is structurally invisible to operations on scope B — the storage layout and the index registry make cross-scope access impossible rather than merely discouraged.

    Concurrency. Implementations are safe for concurrent use from multiple threads. Mutations (Remember/Update/Forget) are serialized per service instance; embedding computation happens outside the serialization gate, so concurrent callers do not block on model latency.

    IScopesAware

    Implemented by stores that can enumerate their scopes natively.
