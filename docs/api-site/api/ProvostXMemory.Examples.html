    Namespace ProvostXMemory.Examples

    Classes

    Ex01_Quickstart

    Minimal end-to-end flow (the README quickstart, made runnable): build a service, remember five facts, build indexes, recall, and print the ranked hits.

    Ex02_Scopes

    Multi-tenant isolation: the SAME record key is written into three tenant scopes with different content; recall in each scope only ever sees that scope's own record, and lookups from a foreign scope find nothing.

    Ex03_HybridSearch

    Hybrid retrieval (BM25-style lexical + dense vector, fused with Reciprocal Rank Fusion): a keyword-only hit and a semantic-only hit answer different halves of the corpus — the fused query surfaces both.

    Ex04_Backends

    Backend parity: the same dataset is loaded into four services — engine Flat, IVF, HNSW, and the zero-dependency FlatJson index — plus the GPU backend (with a fallback note: without a GPU the factory transparently runs its CPU kernels). Every backend returns the same hits; timings are printed per backend.

    Ex05_Consolidation

    Consolidation: near-duplicate records are merged into one survivor plus a cluster summary record; TTL-expired records are deleted. Before/after counts and the summary record are printed.

    Ex06_GraphRetrieval

    Graph retrieval: records mentioning shared entities form an entity/relation graph at index time (heuristic extractor). A graph-connected recall through the entity subgraph surfaces ALL records touching an entity — including records the plain lexical/dense query would miss because they share no query token.

    Ex07_CorrectiveLoop

    Corrective recall: a weak first-pass query is graded, rewritten, and retried. The deterministic fake grader accepts only strong fused hits (both retrieval stages contribute); the built-in keyword rewriter distills the noisy query so the retry pass ranks the target record on top. Diagnostics prove the rewrite-and-retry cycle ran.

    Ex08_LoggingAudit

    Audit logging with hash-chain integrity: file logging is enabled, service operations append chained entries, LogChainVerifier validates the chain — and after one line is tampered with, the verifier pinpoints the broken line.

    Ex09_EvalHarness

    Eval harness: the deterministic seeded corpus is loaded into a fresh service, every golden query is replayed, and a Recall@k / MRR / NDCG report is printed. Identical seeds produce byte-identical corpora and runs.

    Ex10_RestartPersistence

    Restart persistence: records written through the service survive disposal — a brand new service instance rebuilt over the same root recalls them, proving the transactional JSONL store is the durable source of truth (indexes are rebuilt from it).

    ExampleBase

    Base class for every example: one instance, one Run, no static state.

    ExampleRig

    Shared wiring helper for the examples: every service is composed exactly as a host would — MemoryServiceBuilder over the production JsonlMemoryStore, the deterministic ClusterHashEmbedder (no real model, no network), and the own-engine backends. All storage roots live under the temp directory; nothing personal and nothing outside the example's own root is touched.

    ExampleRig.FlatJsonFactory

    FlatJson factory: one VectorNamespaceFile per created scope index, rooted under the example root for realistic restart behavior.

    Program

    Entry point for the runnable example set. With no arguments every example runs in sequence and the process exits 0; pass an example name (e.g. "Ex03_HybridSearch") to run exactly one. Works with no GPU and no network: the embedder is deterministic, the backends are the own engine (CPU) or FlatJson, and storage is a temp directory.
