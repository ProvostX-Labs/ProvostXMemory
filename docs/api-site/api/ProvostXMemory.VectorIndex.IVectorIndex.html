    Interface IVectorIndex

    The pluggable dense-vector index contract. The library ships four backends, all interchangeable through this interface (they pass one shared conformance suite): IndexKind.FlatJson (zero-dependency JSON file, brute-force cosine), IndexKind.Flat (in-memory exact search with SIMD kernels), IndexKind.Ivf (k-means inverted lists for corpus sizes where full scans get expensive), and IndexKind.Hnsw (navigable-small-world graph; built with immutable/rebuild semantics and searched with a layered greedy beam). A GPU tier (ILGPU, transparent CPU fallback) wraps any of these for machines with devices.

    Vector contract: vectors are L2-normalized at index time; scores are cosine similarities (higher = closer, 1.0 = identical). Dim is fixed at construction; every item/query with a different dimension is rejected. Concurrency: implementations own their internal synchronization; concurrent Add/Remove/Search from multiple threads is safe.

    Backends compare sets, not orderings: ranking parity between backends is exact for Flat/FlatJson and statistically guaranteed (recall ≥0.95 on the fixture) for the ANN tiers — results are ranked identically after fusion because ordering derives from scores, not insertion sequence.
