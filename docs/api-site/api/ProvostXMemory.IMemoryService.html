    Interface IMemoryService

    The single public surface of the ProvostXMemory library. Host applications see this interface — plus the options records they pass to MemoryServiceBuilder — and nothing else. Every capability of the library (durable storage, hybrid lexical and dense-vector retrieval, fusion, reranking, optional corrective and graph retrieval, consolidation, and audit-grade logging) is reachable through the members below.

    Scope isolation. Every record belongs to exactly one MemoryScope (platform, session, tenant, purpose, or custom). Every operation is scope-bound; a record written to scope A is structurally invisible to operations on scope B — the storage layout and the index registry make cross-scope access impossible rather than merely discouraged.

    Concurrency. Implementations are safe for concurrent use from multiple threads. Mutations (Remember/Update/Forget) are serialized per service instance; embedding computation happens outside the serialization gate, so concurrent callers do not block on model latency.

    Namespace: ProvostXMemory
    Assembly: ProvostXMemory.dll
    Syntax
    public interface IMemoryService
    Remarks

    A MemoryService is composed via MemoryServiceBuilder: construct the service by wiring the required dependencies (store, embedder, index factory, fuser) and any optional capabilities (grader → corrective loop, graph extractor, reranker, chunker, log sink), then hold the returned IMemoryService for the lifetime of your host.

    Retrieval quality is observable through RetrievalResult diagnostics: every RecallAsync(RetrievalQuery, CancellationToken) returns per-stage scores and timings, which the ProvostXMemory.Eval harness turns into Recall@k / Precision@k / MRR / NDCG reports.

    Examples
    var service = new MemoryServiceBuilder()
    .WithOptions(options)
    .WithStore(store)
    .WithEmbedder(embedder)
    .WithIndexFactory(new EngineVectorIndexFactory())
    .WithFuser(new ReciprocalRankFuser())
    .WithTelemetry(NoopMemoryTelemetry.Instance)
    .Build();

var scope = new MemoryScope(MemoryScopeKind.Session, "user-42");
var fact = new MemoryRecord(
    Id: "fact-1",
    Scope: scope,
    Key: "api gateway",
    Content: "The API gateway binds on port 48321.");
await service.RememberAsync(fact);
var result = await service.RecallAsync(new RetrievalQuery("which port", scope, 5));

    ConsolidateAsync(MemoryScope, ConsolidationOptions, CancellationToken)

    Runs one consolidation pass over a scope: TTL expiry deletes records whose ExpiresAt is in the past, near-duplicates are detected (embeddings with a lexical fallback), the oldest record of each duplicate group is kept with the group's tags unioned in, and sufficiently large near-duplicate clusters emit a summary record. Survivors and summaries are returned as the consolidated set.

    RecallAsync(RetrievalQuery, CancellationToken)

    Routes the query through the configured retrieval pipeline: hybrid dense+lexical search fused with Reciprocal Rank Fusion, optionally reranked; when a grader is wired, a corrective loop grades candidates, rewrites weak queries, and retries once. Scope comes from the query; results never cross scopes.

    Remarks
    An empty or whitespace query text returns an empty result (diagnostics carry the empty-query stage) rather than performing an unconstrained nearest-neighbor search.

    RememberAsync(MemoryRecord, CancellationToken)

    Persists a record and indexes it for retrieval: the record is written to the scope's durable store, then chunks, whole-record, and per-representation entries are embedded and added to the scope's vector index, and the full text is added to the scope's lexical index. A record id that already exists in the scope is rejected.
