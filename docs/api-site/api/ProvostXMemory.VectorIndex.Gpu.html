    Namespace ProvostXMemory.VectorIndex.Gpu

    Classes

    DefaultGpuContextPolicy

    Default policy: GPU-first discovery (CUDA/OpenCL per options), optional CPU fallback acceptance (off by default — availability must reflect real GPUs only). Device selection prefers CUDA > OpenCL and never throws when none exist.

    GpuAccelerator

    Owns the ILGPU Context and the resolved accelerator. The GPU hand-shake runs once, lazily, on first access, inside a lock, and every failure mode (builder exception, missing driver, no acceptable device, accelerator-creation failure) collapses to IsAvailable=false. Nothing here throws for 'no GPU present'.

    GpuDiscoveryOptions

    How the ILGPU context is built for accelerator discovery. GPU-first builders enable CUDA/OpenCL discovery; the flag set mirrors what the host considers acceptable.

    GpuFlatIndex

    GPU-accelerated exact flat index (ILGPU kernel scan). When no GPU is available the injected CPU fallback IVectorIndex is used for every operation with identical semantics — the fallback path must pass the engine conformance suite unchanged. Kernels load lazily; all GPU faults collapse to CPU-fallback execution.

    GpuFlatIndex.Options

    Backend options: ranking metric (default cosine) + launch chunking.

    GpuIvfIndex

    GPU-accelerated IVF index: the deterministic engine k-means partitions the corpus (CPU-side, same algorithm as IvfFlatIndex so partitions are identical), GPU kernels score (1) coarse centroids and (2) in-cluster members. When no GPU is available the injected CPU fallback IVectorIndex is used with identical semantics.

    GpuIvfIndex.Options

    Backend options: mirrors the engine IVF options + ranking metric + launch chunking.

    GpuLaunchOptions

    Kernel-launch policy: rows per launch chunk and the per-launch thread cap. Chunked launches keep the per-thread flat loop short and bounded on every backend (including ILGPU's CPU simulator, which materializes one thread per index).

    GpuMetricCodec

    Mapping from the engine metric enum onto the GPU kernel's int metric code.

    GpuVectorIndexFactory

    Factory that produces GpuFlatIndex for Gpu and delegates every other kind to the injected CPU IVectorIndexFactory. The GPU index receives the standard IGpuAccelerator availability gate and wraps a flat CPU fallback IVectorIndex as its transparent CPU fallback, so search semantics are identical whether or not an accelerator is present.

    GpuVectorKernels

    ILGPU kernels: one thread per score slot, plain loops, no barriers/shared memory — identical accumulation order on every backend (CPU simulator included), so GPU and fallback results are bit-for-bit reproducible for the same inputs.

    GpuVectorMatrix

    GPU-resident row-major vector matrix with lazy (re)upload: CPU-side rows + norms are mirrored to device buffers; uploads overwrite exactly the changed range. Ownership and synchronization live here — indexes never touch ILGPU buffers directly.

    IlgpuScoreLauncher

    Lazy, guarded ILGPU kernel launcher: kernels compile on first launch only (never at construction), launches are chunked per GpuLaunchOptions, and every launch ends with a synchronize so scored results are deterministically visible on the host.

    Interfaces

    IGpuAccelerator

    Availability handle for the ILGPU runtime: owns the Context and exposes the resolved accelerator lazily. Construction never throws and never touches GPU drivers; every member is guarded so machines without CUDA/OpenCL observe IsAvailable=false.

    IGpuContextPolicy

    ILGPU accelerator hand-shake: a GPU-first context (CUDA + OpenCL as configured) with device classes the caller considers acceptable. All discovery is exception- guarded; a machine without GPU drivers simply observes IsAvailable=false.

    IGpuScoreLauncher

    Compiled-kernel launcher boundary: hides ILGPU's launcher delegates behind an injectable abstraction so index classes stay backend-agnostic and testable.
